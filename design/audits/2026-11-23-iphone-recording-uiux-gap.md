## 2. 设计原则与不可退让的质量标准

1. **先数据，再解释，再行动**：首屏 3 秒内辨认今天的核心状态；任何健康结论必须附测量时间、来源和有效窗口；无数据不补假值。
2. **少而清晰的 Hero**：每页至多一个视觉主卡，其他卡片层级从属；不要让十几张等权白卡抢焦点。
3. **原生 iOS、原创视觉**：系统字体、SF Symbols、原生导航/手势；不复制 Bevel 资产或像素布局。
4. **非医疗诊断**：HRV、压力估算、身体年龄、恢复指数不得伪装为经临床验证的诊断；计算方法、可信度和限制可展开。
5. **真实可访问**：浅/深色、动态字体、VoiceOver、Reduce Motion、颜色以外的状态标识；小屏不得裁字。
6. **节制动效**：只为趋势变化、页面过渡、加载状态服务；无数据时不展示伪心电波形。

## 3. 原创设计系统提案（待实际截图验证）

### 3.1 视觉语言

- 名称：**Vital Atlas / 生命图谱**。方向：温润医疗科技、克制高信息密度，非泛滥渐变和卡片墙。
- 浅色背景：`#F5F7F8`；主表面 `#FFFFFF`；一级文字 `#15242B`；二级文字 `#62747D`；品牌青黛 `#176B68`；高亮薄荷 `#D9F1E9`。
- 深色背景：`#0D171B`；表面 `#17262B`；一级文字 `#EDF5F4`；二级文字 `#A9BFC2`；强调色 `#76D8C5`。
- 语义颜色：心脏珊瑚 `#D65F6D`、睡眠靛蓝 `#716BCB`、活动琥珀 `#C78B35`、注意提示 `#B56E22`；所有颜色需在真机按 WCAG 4.5:1 正文对比度及图表区分性实测，不通过则调整。
- 间距：4pt 基础网格；页面左右 20pt；卡间 12–16pt；卡内 16–20pt；主 Hero 圆角 28pt、普通卡 20pt；点击目标不小于 44×44pt，主要操作建议 48pt。
- 字体：使用 Dynamic Type 语义样式，禁止大量固定 10–12pt 的重要说明。重要数值允许大字号但必须支持缩放/换行。
- 图表：实线为真实样本，虚线为推算/参考；缺失区间留空；每张图显示时间范围、单位、最近记录时间、来源和方法说明。不能把插值当测量。

### 3.2 共享组件

`VitalHero`（单页主视觉）、`MetricTile`（名称/数值/单位/窗口/来源/状态）、`TrendChartCard`（时间轴/范围/空样本）、`CoveragePill`（有效样本数及新鲜度）、`InsightCard`（观察/依据/局限）、`StateView`（加载/无数据/读取失败/过期）、`SectionHeader`、`PrimaryAction`（完整交互态）。优先复用既有组件，不新建同名冲突类型；实施前逐文件检索现有 API。

## 4. 七屏改造蓝图

| 页面 | 目标主视觉 | 信息优先级 | 禁止的退化 |
|---|---|---|---|
| 今日 | 今日状态 Hero + 恢复/睡眠/活动三块概览 | 关键状态→近 7 日变化→今日建议→来源 | 以四宫格和大量等权白卡充当整页 |
| 心脏 | 心率时间曲线 + 最新/静息/HRV 分层 | 测量时间→趋势→心率恢复 HRR（仅有足够运动前后样本时）→提醒 | 用单次 HRV 推断诊断、混淆历史与实时 |
| 睡眠 | 昨夜睡眠分期时间轴 + 时长/规律性 | 会话窗口→分期→夜间体征→趋势 | 全日最新体征冒充昨夜测量 |
| 压力/恢复 | 时间分布热力条 + HRV/RHR 关联 | 数据覆盖率→趋势→算法局限→自我观察 | 用静态数字假装实时压力 |
| 健康数据库 | 分类检索 + 指标详情模板 | 类别→最近记录→单位/来源→历史 | 无限同权列表、无筛选和时间口径 |
| 报告 | 扉页摘要 + 分节图表 + 数据覆盖表 | 结论→证据→趋势→缺失项→导出 | 文字堆叠、缺失值按零/正常处理 |
| 设置/权限 | 权限状态和数据同步状态主卡 | 已连接来源→同步时间→错误处理→隐私 | 只显示「已连接」而没有可核查的权限/读取状态 |

注：录屏底部可见五个导航入口；「七屏」是验收范围，不等于强行增加七个底部 Tab。压力/恢复可以在今日的二级导航中进入。
